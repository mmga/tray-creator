# 工程评审与改进建议（产品体验优先）

日期：2026-02-24  
范围：全工程深度审查（重点：产品体验与交互；兼顾性能、稳定性、安全与可维护性）  
约束：不修改代码，仅提出建议与落地方案

---

## 0. 重点结论（先看这里）

1. **Worker 并发请求可能导致生成/导出错位（P0）**：需要引入请求 ID 或队列机制，否则 3D 预览和 STL 导出可能与当前参数不一致。
2. **自动预览与 2D 编辑耦合过深（P1）**：频繁生成导致卡顿/错位，需要更智能的触发条件与“结果过期”提示。
3. **参数导入校验不足（P1）**：对孔径、槽位参数缺少严谨校验，易造成异常模型或 UI 错乱。
4. **画布全局快捷键可能误操作（P1）**：在输入框聚焦或非画布区域也触发删除/移动，易造成无意修改。
5. **失败反馈几乎不可见（P1）**：生成/导出/提交失败仅 console 输出，用户体验断裂。

## 2. 关键体验问题与改进建议（深度审查）

> 优先级定义：  
> **P0** 严重错误 / 结果错乱  
> **P1** 高概率阻断或显著体验受损  
> **P2** 中等体验摩擦 / 性能下降  
> **P3** 体验增强 / 可选优化

### P0 — 结果错乱风险（生成/导出并发）

**现象**  
`src/lib/worker/worker-service.ts` 仅保留“最新 Promise”，未区分请求 ID。任何并发请求都会覆盖前一个请求。  
触发场景：自动预览 + 手动生成；连续多次导出 + 页面生成。

**影响**

- 3D 预览与当前参数不一致
- 导出的 STL 可能对应旧参数（严重）

**建议**

- 为 Worker 请求加入 `requestId`，严格匹配响应
- 增加生成/导出队列或“只保留最后一次生成请求”的取消机制
- UI 明示“生成中 / 结果过期”，避免误导

**涉及**  
`src/lib/worker/worker-service.ts`、`src/hooks/useTrayModel.ts`、`src/hooks/useCustomLayout.ts`

---

### P1 — 自动预览触发逻辑过于“粗放”

**现象**  
`ParameterPanel` / `CustomPanel` 在参数变更后触发 500ms 预览，Custom 模式下拖拽凹槽也会频繁触发生成。

**影响**

- 频繁生成导致卡顿
- 3D 预览“追不上”用户操作，造成错觉

**建议**

- 把自动预览触发限制在“参数面板输入”而非“拖拽槽位”
- 增加“脏状态”提示与“应用变更”按钮
- 生成中禁用二次生成，或只保留最后一次请求

**涉及**  
`src/components/ParameterPanel.tsx`、`src/components/CustomPanel.tsx`、`src/hooks/useCustomLayout.ts`

---

### P1 — 参数导入校验不足（易导致异常模型）

**现象**  
`param-io.ts` 仅校验部分字段，未对 `holeDiameter`、`slots` 的尺寸/旋转/合法性做完整验证。

**影响**

- 导入的 JSON 可能导致 2D/3D 异常
- 用户无法理解“为什么模型出错”

**建议**

- 引入 schema 校验（如 zod），完整校验 `slots`
- 缺省值与钳位策略明确化（非法值回退到默认）
- 错误信息定位到具体字段，增强可理解性

**涉及**  
`src/lib/param-io.ts`、`src/types/custom-tray.ts`

---

### P1 — 全局快捷键可能导致误操作

**现象**  
`useCanvasKeyboard.ts` 使用全局 `window` 监听键盘，输入框聚焦时仍会触发删除/移动。

**影响**

- 用户输入参数时误删除或移动槽位
- 恢复成本高（撤销有限）

**建议**

- 仅当画布获得焦点时启用快捷键
- 输入框聚焦时禁用全局快捷键
- 明确快捷键提示与开关

**涉及**  
`src/hooks/useCanvasKeyboard.ts`、`src/components/LayoutCanvas.tsx`

---

### P1 — 失败反馈不可见

**现象**  
生成或导出失败主要 `console.error`，用户无法感知。

**影响**

- 用户以为成功但结果缺失
- 增加支持成本与信任流失

**建议**

- 统一错误提示（Toast / Banner）
- 给出可执行建议（重试 / 检查网络 / 检查参数）

**涉及**  
`src/hooks/useTrayModel.ts`、`src/hooks/useCustomLayout.ts`

---

### P2 — 2D 碰撞反馈不够“可理解”

**现象**  
碰撞/越界仅用颜色提示，但没有“原因”与“解决方案”提示。

**影响**

- 用户不知道是哪一个槽位冲突
- 布局调整效率低

**建议**

- 在碰撞时显示提示条：“与槽位 X 冲突 / 超出边距”
- 高亮冲突对象
- 提供“自动调整/对齐”快捷入口

**涉及**  
`src/components/LayoutCanvas.tsx`、`src/lib/collision.ts`

---

### P2 — 导出/提交流程缺少进度与取消

**现象**  
导出流程可能耗时较长，但缺少进度条、剩余时间与取消机制。

**影响**

- 用户感觉卡死
- 无法估计完成时间

**建议**

- 显示进度与剩余数量
- 支持取消/暂停
- 失败后可以恢复或继续

**涉及**  
`src/hooks/useTrayModel.ts`、`src/hooks/useCustomLayout.ts`

---

### P2 — “3D 结果是否最新”缺少明确提示

**现象**  
生成结果与当前参数是否一致没有显式标识。

**影响**

- 用户误以为当前 3D 是最新
- 导出或提交错误的模型

**建议**

- 引入“当前参数版本号”或“已同步/未同步”标识
- 参数变更后标注“预览过期”

**涉及**  
`src/hooks/useTrayModel.ts`、`src/hooks/useCustomLayout.ts`、`src/components/TrayViewer.tsx`

---

### P2 — 撤销历史可能“过快耗尽”

**现象**  
拖动和参数调整频繁触发 `pushState`，历史上限固定 50。

**影响**

- 用户不确定能撤销到哪一步
- 大量操作时恢复困难

**建议**

- 对连续拖拽/滑动做合并（throttle/commit）
- 提示剩余撤销次数或“最近一次保存点”

**涉及**  
`src/hooks/useUndoHistory.ts`、`src/hooks/useCustomLayout.ts`

---

### P2 — 2D/3D 结果存在“公差心智差”

**现象**  
3D 中应用了 `HOLE_TOLERANCE`，但 2D 显示不一定体现。

**影响**

- 用户以为布局合理，实际打印边距不足
- 产生“实物与预览不一致”的感知

**建议**

- 2D 显示层也体现公差
- 在 UI 中明确显示“实际凹槽直径 = 标称 + 公差”

**涉及**  
`src/lib/config.ts`、`src/components/LayoutCanvas.tsx`、`src/lib/tray-model.ts`

---

### P2 — 移动端交互可发现性不足

**现象**  
移动端右键菜单由长按触发，缺少引导；快捷键提示仅靠 `?`。

**影响**

- 新用户不知道“长按/快捷键”
- 学习成本高

**建议**

- 首次进入显示“手势引导”
- 在画布角落常驻“操作提示”按钮

**涉及**  
`src/components/LayoutCanvas.tsx`

---

### P3 — 3D 预览性能自适应不足

**现象**  
模型复杂度高时仍固定高质量渲染。

**影响**

- 低端设备发热 / 卡顿

**建议**

- 添加“性能模式”开关（降低线框/边缘线/抗锯齿）
- 大尺寸模型自动切换低质量模式

**涉及**  
`src/components/TrayViewer.tsx`、`src/lib/config.ts`

---

### P3 — 可访问性与可用性增强空间

**现象**  
按钮/交互控件缺少显式 aria 与键盘可达路径说明。

**建议**

- 为关键按钮补充 aria-label
- 在 UI 中明确键盘路径（尤其是撤销/复制/删除）

**涉及**  
`src/components/*`

## 3. 优先级路线图（建议）

### Quick Wins（1–2 周）

- Worker 请求 ID / 单次生成机制
- 错误反馈可视化（Toast/Banner）
- 画布快捷键作用域限制
- 预览过期提示

### Medium（2–4 周）

- 参数导入 schema 校验
- 自动预览策略优化（脏状态 + 用户确认）
- 2D 碰撞反馈优化
- 导出进度与取消机制

### Large（1–2 月）

- Admin API 后端化
- 3D 渲染自适应策略
- 引导与教学体系（新手引导/帮助中心）

## 5. 建议测试场景（验收）

- **并发生成**：快速修改参数 + 手动点击“开始锻造”，确认预览与参数一致
- **导入错误文件**：缺字段/异常字段/极端参数
- **大量凹槽**：拖拽/缩放/对齐响应是否流畅
- **移动端长按**：能否直观发现并使用上下文菜单
- **批量导出**：进度可视化、可取消、失败恢复
- **Admin/公用模式切换**：权限与功能是否清晰隔离
