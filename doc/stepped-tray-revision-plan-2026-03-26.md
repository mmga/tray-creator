# 自定义阶梯底座修订方案

> 日期：2026-03-26
> 适用范围：Stepped Mode（自定义阶梯底座）
> 目的：基于 2026-03-26 评审结论和产品取舍，收敛为一版可执行的修订方案

---

## 1. 本次确认的产品决策

### 1.1 问题 1：增加“槽群断连距离”控制

结论：**建议做，但放在自动预览移除之后作为第二阶段优化。**

目标不是简单提示“算法有问题”，而是给用户一个明确、可控的参数，决定“相距多远的槽群即使在平滑轮廓下也不应该被桥接为一个整体”。

### 1.2 问题 2：取消自动预览

结论：**立即执行。**

Stepped Mode 不再在参数变化后自动生成模型，只能通过点击“开始锻造”按钮触发生成。

### 1.3 问题 3：并发/竞态问题

结论：**先通过取消自动预览降低问题暴露面。**

本轮不单独引入更复杂的请求淘汰或任务序号机制，先用“仅手动生成”将主要竞态入口关掉。

### 1.4 问题 4：复用导出参数模块

结论：**立即执行。**

STL 导出时附带的 JSON 参数文件必须复用统一的参数导出协议，不能再手写裸 params JSON。

### 1.5 问题 5：移动端问题

结论：**本轮忽略。**

移动端 stepped 预览与桌面行为不一致的问题先不处理，避免本轮改动范围扩散。

## 2. 修订后的实施范围

### P0：本轮必须完成

1. 取消 Stepped Mode 自动预览
2. 统一 Stepped Mode 的“预览已过期”提示逻辑
3. 统一 STL 附带 JSON 的导出格式，复用参数导出模块

### P1：下一轮建议完成

1. 新增“槽群断连距离”参数
2. 在面板中提示当前参数会让多个槽群被连成一体
3. 给出两类操作建议：
   - 增大断连距离阈值
   - 调整槽位位置或减小平滑半径

### 明确不在本轮处理

1. 移动端 stepped 视图一致性
2. Worker 任务淘汰机制重构
3. 多连通域轮廓算法的彻底重写

## 3. 详细修改方案

## 3.1 取消自动预览

### 目标

Stepped Mode 中，任何参数变化、分组变化、导入、重置、撤销后，都只更新状态，不自动触发 3D 建模。

### 预期交互

1. 用户修改参数
2. 左侧面板或 3D 视图显示“当前预览已过期”
3. 用户点击“开始锻造”
4. 生成完成后清除过期状态

### 具体修改点

#### [src/components/SteppedPanel.tsx](src/components/SteppedPanel.tsx)

1. 删除 `autoPreview` 本地状态
2. 删除自动预览 `useEffect`
3. 删除“启用自动预览”开关 UI
4. 保留“开始锻造”作为唯一生成入口

#### [src/hooks/useSteppedLayout.ts](src/hooks/useSteppedLayout.ts)

1. 所有会改变 stepped 参数的路径都必须将 `isPreviewStale` 设为 `true`
2. `handleGenerate()` 成功后再将 `isPreviewStale` 设为 `false`
3. 对整包替换参数的入口补足失效逻辑，避免“新参数 + 旧模型”

### 直接收益

1. 消除自动预览引起的主要并发入口
2. 让用户明确知道何时需要重新生成
3. 降低大模型参数调整时的性能压力

---

## 3.2 问题 3 的临时处理方式

本轮不做复杂并发治理，采用更务实的控制方式：

1. 去掉自动预览，减少后台自动排队请求
2. 保持“生成中”按钮禁用，避免同一时刻重复点击
3. 将并发风险从“高频自动触发”降为“低频手动触发”

### 风险说明

这不是彻底修复。理论上用户仍可通过极端操作制造边缘竞态，但对当前产品阶段来说已经足够把问题从高频降到低频。

## 3.3 复用导出参数模块

### 当前问题

Stepped Mode 导出 STL 时，会额外生成一个 JSON 文件，但该文件目前只包含裸 `params`，不是系统统一的导入导出格式。

这会导致：

1. 管理员导出的 JSON 不能直接重新导入
2. 导出协议分叉，后续维护成本增加

### 目标

STL 附带参数文件必须与“导出参数”按钮生成的 JSON 格式完全一致。

### 具体修改点

#### [src/hooks/useSteppedLayout.ts](src/hooks/useSteppedLayout.ts)

不要再手写：

```ts
JSON.stringify(params, null, 2);
```

而是改为复用统一参数导出逻辑，保证输出结构包含：

```json
{
  "version": 1,
  "mode": "stepped",
  "params": { ... }
}
```

### 推荐实现方式

优先抽取一个“序列化参数为 JSON 字符串或 Blob”的共享函数，由以下入口共同复用：

1. 导出参数按钮
2. STL sidecar JSON

这样可以避免通过 DOM 下载逻辑去反向复用 UI 层函数。

## 3.4 新增“槽群断连距离”参数

### 需求意图

当前 stepped 轮廓依赖平滑半径和圆形外扩做形态学闭运算。这样在视觉上能得到更自然的过渡，但也会带来一个产品问题：

**两个离得不算很远的槽群，可能被算法自动桥接成一整块。**

用户真正需要的不是单纯知道“算法把它们连起来了”，而是能主动指定：

“如果两个槽群之间的最小间距超过某个阈值，就不要连。”

### 参数建议

建议新增全局参数：

- 参数名：`disconnectDistance`
- 中文名：槽群断连距离
- 类型：number
- 建议范围：0 到 60 mm
- 默认值：0 或一个保守值（建议先从 0 开始，保持与当前行为兼容）

### 参数语义

1. `disconnectDistance = 0`
   - 保持当前行为
   - 允许算法按平滑半径自然桥接

2. `disconnectDistance > 0`
   - 当两个槽群的最短边缘距离大于该阈值时，强制分为不同连通域
   - 即使平滑轮廓理论上能把它们桥起来，也不要合并成同一块底座

### 实现建议

不要在轮廓生成的最后阶段“事后拆开”，而应该在进入形态学闭运算前先做聚类。

推荐流程：

1. 先基于槽位外扩圆计算槽与槽之间的边缘距离
2. 以 `disconnectDistance` 为阈值做图连通分组
3. 每个连通分组单独生成 outline
4. 最终将多个 outline 分别挤出并 union

这样做的好处：

1. 逻辑清晰，可预测
2. 便于后续修复“多连通域只保留最大岛”的根本问题
3. 用户可直接通过参数理解模型为什么断开或连通

## 3.5 在哪里提示这个问题

### 提示目标

当用户当前参数会让多个槽群被连成一块，系统应给出可操作提示，而不是只显示一个抽象警告。

### 建议提示位置

#### 首选位置：SteppedPanel 的“结构参数”或“统计信息”区块

原因：

1. 用户调 `smoothingRadius` 时就在这一块
2. 用户看到警告后可以立即改参数
3. 不依赖 2D 画布，桌面与移动端都能共用文案逻辑

### 提示文案建议

当检测到“当前会桥接多个槽群”时，显示：

> 当前参数可能会将 2 个或更多槽群连接为一个整体底座。
> 你可以尝试增大“槽群断连距离”、减小“平滑半径”，或调整槽位位置。

### 可选增强

如果后续要继续增强，可以额外显示：

1. 当前识别到的槽群数量
2. 预计会被连接的槽群数量
3. 一键跳转到对应参数区块

## 4. 建议的落地顺序

### 第一阶段

1. 删除自动预览 UI 与逻辑
2. 统一 `isPreviewStale` 的状态更新
3. 修正 STL sidecar JSON 导出协议

### 第二阶段

1. 增加 `disconnectDistance` 配置、默认值和校验
2. 在 stepped 轮廓生成前做槽群聚类
3. 在面板增加桥接风险提示

### 第三阶段

1. 若仍发现孤立岛丢失，再推进 outline 多连通域重构
2. 如用户频繁要求自动刷新体验，再单独设计安全的生成任务治理机制

---

## 5. 验收标准

### P0 验收

1. 修改 stepped 任意参数后，不会自动生成模型
2. 只有点击“开始锻造”才会生成
3. 参数变化后界面能明确提示当前预览已过期
4. 导出的 STL 附带 JSON 能被系统重新导入

### P1 验收

1. 存在多个相距较远的槽群时，可通过 `disconnectDistance` 控制是否断开
2. 参数面板能明确提示“当前会被桥接”的情况
3. 用户能通过调参数或改位置解决提示的问题

---

## 6. 最终建议

本轮建议不要试图一次性把 stepped 的所有结构问题全部修完，而是先完成两件真正高价值的事：

1. 去掉自动预览，稳定交互链路
2. 统一参数导出协议，修复导出/导入闭环

在此基础上，再推进“槽群断连距离”这个更符合用户心智的控制参数。这个参数一旦落地，会比单纯修一个算法 bug 更有产品价值，因为它把“连不连”从系统猜测变成了用户决策。
