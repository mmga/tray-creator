# 继续长期运行项目

本 workflow 实现编码代理的 10 步工作流，每次对话专注完成 1 个功能。

## 步骤

### 1. 了解当前状态 (必须)

读取以下文件来了解项目进展：

// turbo
```bash
cat claude-progress.txt
```

// turbo
```bash
git log --oneline -10
```

然后读取 `feature_list.json`，统计：
- 总共多少个功能
- 已通过多少个 (`"passes": true`)
- 下一个要做的是哪个 (`"passes": false` 中优先级最高的)

向用户汇报当前状态。

### 2. 回归测试 (重要)

在开始新功能前，快速检查 1-2 个已标记为 `passes: true` 的核心功能是否仍然正常工作。

如果发现问题：
- 立即在 `feature_list.json` 中将该功能的 `passes` 改回 `false`
- 先修复问题，再做新功能
- 更新 `claude-progress.txt` 记录发现的问题

### 3. 选择 1 个功能

从 `feature_list.json` 中选择 **优先级最高的、尚未通过的** 功能。

告知用户你选择了哪个功能，等待确认（用户可能想调整优先级）。

### 4. 实现功能

专注实现这一个功能：
- 编写前端和/或后端代码
- 确保代码质量（类型安全、错误处理等）
- 不要同时做多个功能

### 5. 验证功能

通过实际 UI 验证功能是否正常：
- 如果是 Web 应用，使用浏览器工具访问页面
- 截图验证视觉效果
- 测试完整的用户操作流程
- 检查是否有控制台错误

### 6. 更新 `feature_list.json`

**只能修改 `passes` 字段**，将已验证的功能改为 `true`：

```json
"passes": true
```

**绝对不允许：**
- 删除任何功能
- 修改功能描述
- 修改测试步骤
- 合并或重排功能

### 7. Git 提交

// turbo
```bash
git add . && git commit -m "Implement: [功能描述] - verified"
```

### 8. 更新 `claude-progress.txt`

追加本次会话的记录：
```
## Session N - (日期)
- 实现了: [功能描述]
- 测试 #X 标记为通过
- 发现/修复的问题: [如有]
- 当前进度: X/N 测试通过
- 下一步建议: [下一个功能]
```

### 9. 汇报进度

告知用户：
- 本次完成了什么
- 当前进度 (X/N 通过)
- 下一个要做的功能是什么
- 如果要继续，使用 `/continue` 命令
